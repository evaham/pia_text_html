1. 기술연구소(POS개발팀) 보고


(1) 투게더POS 및 딜리버리


- 진행 상황

* 지난주부터 투게더 딜리버리의 실제 매장 사용 시작

* 실사용 과정에서 수집된 피드백 가운데 우선 처리 가능한 항목을 반영하여 1차 개선 버전 준비

* 토마토 식자재 운영 매장에서 발생한 개선 요청사항 확인 및 수정 진행

* MGR·OPR은 별도 중대 이슈 없이 고객 요청과 일반 수정사항 처리 중


- 일정 및 조치

* 개선 버전의 배포 일정을 회의에서 논의. 대표이사 지시에 따라 10월 19일 배포를 우선 추진

* 배포 이후 추가 현장 피드백을 지속적으로 수집해 후속 개선에 반영



(2) 투게더POS 라이트


- 개발 및 업무분장

* 솔루션본부와 개발 업무분장 협의 진행

* 모바일 앱과 관련 API는 노정원 담당자가 통합 개발하는 방향으로 정리

* 초기 라이트 앱의 기능 범위가 크지 않고 개발 난이도도 상대적으로 낮아 통합 개발 방식이 효율적이라고 판단

* 앱과 API를 별도 담당자가 개발할 경우 발생하는 인터페이스 협의와 일정 지연을 줄이려고 함


- 기타 개발사항

* 센터 서버 구성 및 인증 프로세스 정비. POS 라이트 관련 실행·배포 파일 준비

* 정식 외부 배포보다 다른 PC에서 동작을 확인할 수 있는 내부 QA 및 시연용 환경 구축을 우선 진행


★ 기획팀과 개발부서가 협의하여 POS 라이트 전체 개발계획을 한 장으로 정리

★ 기능별 개발 범위, 담당, 완료 예정일, 테스트 및 출시 예상 시점을 명확히 표시

★ 내부 개발 완료 시점뿐 아니라 실제 시장 공급이 가능한 시점까지 예측할 수 있도록 작성



(3) 토스프론트 연동

- 토스프론트 및 결제처리와 관련된 추가 실무회의 진행

- 프론트 기능 및 결제모듈에 필요한 추가 개발사항 확인. 솔루션본부와 협업하여 보완 개발 진행 중.



(4) 투게더 프로모션

- 프로모션의 구매·할인 유형 추가 개발 진행

- 금주 개발 완료 후 차주 초 운영 배포를 목표로 준비

- 관련 웹·서버 기능은 선행 배포 일정과 연계하여 진행

3. 솔루션본부 보고


(1) 마트킹 통합 상품 데이터베이스 구축


- 사업 내용

* 마트킹의 SI 시스템 구축 외에 별도의 통합 상품 데이터베이스 체계 구축 진행

* 마트킹 담당자들과 구글시트를 이용해 실시간으로 상품분류 기준을 협의 (1,271개 상품분류 코드 구성)

* 마트킹의 식자재 특성에 맞추어 기존 상품분류 체계를 확장.

* 기존 3단계 분류에 상위 그룹 개념을 활용하여 4단계 수준의 분류체계 구성


- 데이터 규모 및 특성

* 전체 원천 상품 레코드는 약 214만 건으로 언급 

* 투게더데이터 상품 레코드(공산품 데이터 76만 건)과 차이가 나는 이유: 인스토어 바코드 100만 건 이상 존재하기 때문

* 인스토어 바코드는 매장별 상품코드가 달라 공통 상품장으로 통합하기 어려움


- 정제 방식

* AI를 활용해 상품별 분류를 1차 매핑

* 마트킹 담당 TF에서 AI 분류 결과를 확인

* 기존 상품분류에 연결된 상품을 신규 분류체계로 재배치

* AI 결과만으로 높은 정확도를 확보하기 어려우므로 육안 검수 병행


- 작업 일정

* 10월 21일~30일 동안 상품분류 및 데이터 검증 작업 진행 예정

* 마트킹과 최종 분류체계를 확정한 이후 데이터 정제 진행



(2) 마트킹 API 연동

* 마트킹 측과 API 연동 개발 협의 완료

* 개발 관련 API 문서 수령 후 담당 개발자에게 전달

* 금주 중 개발을 진행하여 정식 배포 없이 내부 알파테스트를 실시할 예정

- 구글 정책 변경에 따라 앱의 개발도구 및 관련 패키지를 갱신해야 하는 상황
